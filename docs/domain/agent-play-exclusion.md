## Analytics exclusion for agent-originated plays (#129)

Composes with the existing play-validity filter (`c69c6f17`, `MIN_VALID_MS=30_000`, `temporal._is_valid`) rather than replacing it — the two filters are orthogonal: a play can be validity-passing (long enough to count as a real listen) **and** analytics-excluded (agent-originated) at the same time. Decision `1c0f37f0`.

- **Exclusion is source-tag-driven, not backfill-driven.** #129's own AC wording ("plays originating from the S6 backfill queue or S7 automated playback") is broader than what actually exists: the #127 backfill playlist never emits `ListenEvent`s itself — it only manages Spotify playlist membership, so a user genuinely playing a backfill-queued track produces an ordinary user-initiated event, indistinguishable from any other real listen. Only #128's automated playback stamps a distinct origin (`AUTOMATED_PLAYBACK_SOURCE`, see above). `analyzer._is_user_initiated(source)` therefore checks exactly `source != AUTOMATED_PLAYBACK_SOURCE` — no heuristic guess, per AC4.
- **`exclude_agent_originated: bool = True` threads through `analyze()` → `_group_and_seed()` → `_temporal_plays()`.** On by default (opt-in override to include them, off by default, per AC2). Agent-originated events are dropped before they ever reach the audio/scene seed set, the play-count evidence map, or *either* of `_temporal_plays`'s filtered/unfiltered maps — unlike the validity filter, origin exclusion is a data-*source* gate (this play didn't happen because the user chose to listen), not a data-quality gate on organic data, so it applies to epoch detection too, not just the lift-facing filtered map.
- **Composition with `_is_valid` is proven by evaluating both independently**, not by fusing them into one boolean expression: with the origin override off, an agent-originated play still passes/fails `_is_valid` on its own merits (see `test_temporal_plays_composes_origin_exclusion_with_validity_filter`), so neither filter short-circuits the other.
- **The replay-window ledger (#167 AC1/AC2) feeds the same `source` discriminator, not a second exclusion path.** `spotify_extended.py`'s ESH importer reads the ledger (`load_replay_ledger_windows`, parsing `replay_ledger.jsonl` directly rather than importing `ReplayLedgerEntry`'s pydantic schema, to stay decoupled from `replay_capture.py`) and tags any row whose `played_at` falls inside a window with `source = AUTOMATED_PLAYBACK_SOURCE` — a **tag, not a drop** (decision `83bd6f76`/`9576bde1`'s lossless-projection stance: the row still imports, its skip/import counts are unaffected, only `source` changes). It is then invisible to `analyze()`'s default `exclude_agent_originated=True` exactly like a `build_automated_play_event`-sourced row, with zero new code in `analyzer.py` — `_is_user_initiated(source)` already checks exactly `source != AUTOMATED_PLAYBACK_SOURCE`. The importer's printed summary (#167 AC3) surfaces the tagged count separately from the existing skip counts (`ledger-tagged N rows as agent-originated`), since tagging is not skipping.
