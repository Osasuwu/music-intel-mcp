8. ~~Audio analysis infrastructure (V1).~~ → **resolved, grilled 2026-08-19** (decisions `3ca7565c` sequencing, `16d7f570` engine, `1c0f37f0` sourcing, `29852699` storage/licensing; plan + AC in #109). **Engine:** MTG pretrained models (Discogs-EffNet embeddings → MTG-Jamendo heads) consumed as ONNX via `onnxruntime`, with `librosa` as the signal frontend — the Essentia *library* is dropped (no Windows wheels; verified locally, MTG/essentia#859). **Sourcing:** passive playback capture — WASAPI loopback (per-process preferred), listen-analyze-discard, audio never persisted; previews and DRM caches are rejected paths (ToS / encryption, researched — do not revisit without new evidence). **Backfill:** opt-in auto-managed "to-analyze" playlist (≤10k, daily refresh, remove-on-analyzed) + optional consented automated playback; all instrumental plays excluded from taste analytics unless opted in. **Dedup** (#126, decision `1c0f37f0`): track-level, purely off the identity waterfall + local `UserStore` — no new external dependency. `UserStore.has_audio_analysis(track_id)` gates `run_live_capture_spike` before the expensive inference step; an already-analyzed track returns `LiveCaptureResult(skipped=True, inference=None)` with no re-inference. Concurrent-duplicate race is **first-write-wins, not merge** — `UserStore.write_audio_analysis` claims the file atomically via `os.open(path, O_CREAT | O_EXCL | O_WRONLY)`; a losing concurrent writer's payload is silently discarded (`FileExistsError` → return the winner's path) rather than averaged, since embeddings aren't meaningfully averageable. New tracks (no store entry) are auto-identified and analyzed on their next play via the existing polling loop (`continuous_capture.py`) — no manual trigger. **Scaling:** multi-user pooling, gated on licensing. **Licensing:** MTG models are CC BY-NC-ND 4.0 (LICENSE file authoritative over models.html; the model files themselves stay non-redistributable; the only other condition MTG attached is AGPL on Essentia's *own* algorithms if those compute the model input, which does not apply since the front-end is librosa); PANNs fallback for the shared tier (licence motive gone as of the same decision), licence corrected 2026-09-06 (decision `24458ec3-eb48-4714-bae3-23f387517f16`): code is MIT (canonical `qiuqiangkong/audioset_tagging_cnn` repo, confirmed via GitHub API), pretrained weights are CC BY 4.0 (Zenodo record `3576403`) — permissive either way, and the cleaner licence footing of the two for the pooled path; compute always local. **Pre-slice:** text/crowd-tag coverage push (Last.fm/MusicBrainz/Discogs) lands before audio work. **Clustering substrate** (decision `0c762eec`): per-track embeddings stored, audio roots clustered in embedding space — tags/scalars are cluster descriptors only. **Mobile capture** (decision `b1f30549-7a83-4e2e-82df-e657fe546e72`, #118, confidence 0.75): Android `AudioPlaybackCapture` is a no-go for Spotify specifically (manifest sets `android:allowAudioPlaybackCapture="false"`, confirmed via decompiled manifest) and iOS has no passive-capture API at all (ReplayKit is user-initiated, per-session only, per Apple docs) — so the pilot's existing Type B design (one-shot ESH export + node-side replay, not mobile-side capture) already sidesteps this for pilot scope. At-scale/post-pilot fallback recommendation: `NotificationListenerService`/`MediaSession` metadata-only capture, which is unaffected by an app's audio-capture opt-out (separate OS contract, confirmed via Android docs) — YouTube Music's manifest value is unconfirmed (evidence gap, flagged not papered over). Lyrics pillar (#119) and structure×skip (#120) spun off as separate feature-space branches.

14. ~~Timestamp timezone.~~ → **resolved + wired in #90** (decisions `d2c1ff60`, `498eb9d1`, `77111ce0`). Temporal buckets condition on **local wall-clock**, keyed on **`event.source`**: `spotify_extended` (honest UTC `ts`) always shifts via a `conn_country → IANA-region` map with a per-user modal-zone fallback (real IANA regions only, never `Etc/GMT±N`, so the KZ 2024 UTC+6→+5 transition is honored); **IFTTT** (zone-less local wall-clock) is treated as **already local and never shifted**. Source-keying dissolves the earlier "IFTTT is the harder residual" framing — it needs no pinned source zone or per-event zone carry, because its wall-clock *is* the local time; its only residual is that the wall-clock is the *account* zone not the device (traveler smear), logged per-source but not corrected, and moot on owner data (`import-spotify` supersedes IFTTT). Separately, the validity filter feeds lift/stability while epochs run **unfiltered** (decision `77111ce0`, to avoid manufacturing epochs from the non-stationary skip rate). No longer blocks anything — this is the #90 slice.
