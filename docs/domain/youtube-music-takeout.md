## YouTube Music (Google Takeout) watch-history ingestion (#164)

A pilot slice for a participant whose listening history lives in **YouTube Music**, not Spotify — Google's per-account **Takeout** export is the only available source, distinct from every Spotify-derived path above. `src/music_intel_mcp/youtube_music.py` is the adapter; `music-intel import-youtube --from <watch-history.json> [--data-dir ...]` merges it into the per-user `history.jsonl`. The browser-URL replay driver originally scoped alongside this is deferred post-pilot (decision `d6c9ffe0`) — this importer ships only the import side.

- **Takeout `watch-history.json` format.** Google's Takeout ships the participant's **entire** watch history (YouTube + YouTube Music combined) as a single JSON array, one object per watched video, in Google's real export order (newest-first) — the importer does not assume an order and sorts via the same `dedup_events` every other source uses. Load-bearing fields per row: `header` (`"YouTube Music"` for a music play; any other value — e.g. plain `"YouTube"` — marks a non-music video watch and is skipped, counted, never imported), `title` (`"Watched <title>"`, or the exact sentinel `"Watched a video that has been removed"` for a since-deleted video with no `titleUrl`), `titleUrl` (`"https://music.youtube.com/watch?v=<id>"` — the video id lives in the `v` query param; absent entirely for a removed video), `subtitles` (`[{"name": "<Artist> - Topic", ...}]` — the channel name, carrying a trailing `" - Topic"` suffix for an auto-generated-upload channel, stripped on import), and `time` (an ISO-8601 UTC `...Z` timestamp, the same shape as Spotify Extended's `ts`). Every row the importer excludes — non-music header, removed video, no extractable video id, unparseable timestamp — is tallied on `YoutubeMusicStats` and printed by the CLI, never silently dropped (same lossless-projection, drop-accounting discipline as every other importer in this section).
- **Identity: the `youtube_id` rung, not name/artist matching.** Unlike the Account Data StreamingHistory importer above (which must resolve identity by fuzzy name/artist lookup because its source carries no native id), a Takeout row's video id **is** a stable native identifier — `TrackRef.youtube_id` carries it directly, and `canonical_track_id()` yields `youtube:<id>` when no richer id (mbid/isrc/spotify id) exists for that track (the identity waterfall's fourth rung, after mbid/isrc/spotify_id and before the name/artist fallback). This is why `account_history.py`'s Spotify-only-scoped name/artist lookup does not need to (and does not) generalize to YouTube Music.
- **No-duration validity rule.** Takeout carries **no play-duration signal at all** — there is no `ms_played`, no `skipped`, no equivalent of any per-play context field the Spotify sources carry. A YouTube Music entry counts as a full valid play on presence alone (a parseable timestamp + a resolvable video id); `ListenEvent.context` is always `None` for this source. This is a stricter validity rule than every Spotify path (which carry `ms_played`/`skipped` losslessly even though V0 applies no import-time filter) — here there is nothing to carry, because Takeout never recorded it.
- **Self-referential supersede + idempotency (AC3).** `youtube_music.SUPERSEDES = frozenset({SOURCE})` — no existing source's history overlaps YouTube Music watch history, so re-import only ever displaces a **prior run of this same importer**, never another source's events (contrast the cross-source supersede between `ifttt`/`spotify_extended`, or the time-cutoff merge against `spotify_extended` above). `import-youtube` filters `before` by `event.source not in SUPERSEDES`, then merges and dedups via the shared `dedup_events()` — re-running over the same or an updated export is idempotent and never duplicates a play. No #93-style not-a-superset guardrail is needed here: unlike Spotify's potentially-partial per-run exports, Google Takeout always ships the complete watch history in one file, so there is no partial-export risk to warn about.
- **⚠ 36-month auto-delete caveat.** Google/YouTube's own retention policy auto-deletes YouTube watch history older than the account's configured retention window (commonly 18 or **36 months**, user-configurable in the account's Activity Controls) unless the participant has explicitly set retention to "keep until I delete manually." A Takeout export therefore reflects **whatever the live retention window has not yet erased**, not necessarily the participant's full historical listening — an import that looks thin relative to the participant's actual listening tenure may simply be hitting this ceiling, not a bug in the importer. This is a source-side data-completeness caveat, not something `youtube_music.py` can detect or work around; documented here so a short-looking import isn't mistaken for a parsing gap.
