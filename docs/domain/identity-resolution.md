## Identity resolution (V0)

The **identity waterfall** turns whatever id a history event happens to carry into the one stable join key the enrichers need — the MusicBrainz **recording MBID** (the key into the AcousticBrainz/MusicBrainz dumps for #63/#64). Python: `src/music_intel_mcp/identity.py`. Issue #61.

Waterfall, deepest rung wins: **`mbid`** (already present, passthrough) → **`isrc`** → MBID via the MB dump → **`spotify_id`** → ISRC (Spotify) → MBID. The rung reached is the `ResolvedIdentity.level` ∈ {`mbid`, `isrc`, `spotify`, `name`}; only `mbid` counts as *resolved* (`ResolvedIdentity.resolved`).

- **`IsrcMbidIndex`** (Protocol) — `lookup(isrc) -> mbid|None` (the single disambiguated best) **plus `lookup_all(isrc) -> list[str]`** (every candidate MBID), the dump leg. `MusicBrainzIsrcIndex` reads a prebuilt `<isrc>\t<mbid>` TSV extract — **multi-valued**: repeated ISRC rows accumulate into a candidate list (dup MBIDs collapsed, first-seen order kept). Path is **env-pointed** (`MUSICBRAINZ_ISRC_INDEX`, falling back to `$MUSICBRAINZ_DUMP_DIR/isrc_to_mbid.tsv`) and **never committed** — a missing file yields an empty index (honest low coverage, never a crash). `InMemoryIsrcMbidIndex` is the test fixture (accepts `{isrc: mbid}` or `{isrc: [mbid, ...]}`).
- **`SpotifyIsrcSource`** (Protocol) — `lookup(spotify_id) -> isrc|None`, the Spotify leg. Optional: when absent, spotify-only tracks are honestly flagged at the `spotify` level, not dropped. The live implementation is **`SpotifyApiIsrcSource`** (`spotify_api.py`, #87 AC-A): client-credentials token (cached in-memory to just before expiry), batch `GET /v1/tracks` (≤50 ids), ISRC from `external_ids.isrc`, backoff on 429/503 (`Retry-After` honored). It owns a **persistent JSONL sidecar cache** storing hits *and* misses keyed by bare spotify id, so a re-run — or a resumed, interrupted `warm` — skips ids already asked about (`scene-warm-negative-cache-resume`). `warm(ids)` is the batching prefetch (extra method, not on the Protocol); `lookup` is the Protocol contract (cache read, single-id fetch fallback). `GET /tracks` carries ISRC and is *not* one of our constrained endpoints.
- **`IdentityCache`** (`data/identity/<input-key>.json`) — keyed by the *input* canonical id, so a re-run with the same history **skips the waterfall entirely** (no re-resolution). Regenerable + gitignored, percent-encoded filenames (shared `encode_cache_key` with the metadata cache).
- **`ResolutionReport`** — keyed by input canonical id (deduplicated). Derives `counts` (per-level ledger), `mbid_coverage` (fraction resolved to MBID — feeds `generated_from.coverage_per_category`), and `unresolved` (input keys that did not reach MBID — **flagged, never dropped**, per the transparent-rejection invariant). `to_metadata_records(report, now)` writes resolved identities back to the shared store, keyed by the *resolved* canonical id (so the store dedups across users by MBID).

The same `canonical_track_id()` waterfall (mbid > isrc > spotify > name/artist) is the single source of truth for track keys — the analyser's unique-track counting now calls it directly (the old `analyzer._track_key` tuple was folded into it).

**Measured reality on the owner's real library** (120-track deterministic KZ-heavy probe against live MB/AB, decision `2b262dc9`). The history export carries `spotify_id`s, **not** ISRCs — so a bare ISRC→MBID index resolves **~0** on its own. Resolution is a **2-link chain**: `spotify_id → ISRC` (Spotify `GET /tracks`, the `SpotifyIsrcSource` leg) → `ISRC → MBID` (the MB dump). Wiring only one leg yields 0% MBID → honest-empty regardless of thresholds. Measured ceilings on the full chain: **ISRC→MBID 56.7%** unique / **62.3%** play-weighted; the URL-relationships path adds only +0.8pt over ISRC on the tail (**rejected** — not worth a second live call per track). The unresolved tail is low-popularity regional (KZ) music MusicBrainz does not index (resolved-set popularity 36.3 vs unresolved 17.7; 31/51 unresolved below popularity 20).
- **`resolve --with-spotify` fires the spotify→ISRC leg** (#87 AC-A, wired). Off by default `_cmd_resolve` still passes `spotify_source=None` (offline, spotify-only tracks flagged at the `spotify` rung). With `--with-spotify`, `plan_spotify_source(with_spotify, env, data_dir=…)` gates on `SPOTIFY_CLIENT_ID`+`SPOTIFY_CLIENT_SECRET` **presence** (missing → `error:` + rc 2, before any network — mirrors the `LASTFM_API_KEY` gate on `--with-scene`), builds `SpotifyApiIsrcSource`, `warm`s every history spotify id once (batched prefetch), then hands it to the resolver so the per-track waterfall reads the local cache. **Capability-drift caveat:** `IdentityCache` short-circuits on the *input* key before consulting `spotify_source`, so a cache written by a no-spotify run is stale for a later `--with-spotify` run — an honest-measurement run (AC-E) must start from a clean `identity/` dir. The expensive API path is independently deduped by the spotify JSONL sidecar, so this only re-walks the cheap in-memory waterfall.
- **Spotify's ISRC is not authoritative** (F9, documented limitation). Labels reissue/mislabel ISRCs; a wrong-but-present ISRC resolves to a plausible-but-wrong MBID with no signal that it happened. Accepted as a known V0/V1 error source — not corrected here, flagged so downstream calibration reads coverage as *approximate*.
- **One ISRC can map to many recordings — built, #87 AC-B.** The MB index is multi-valued; `disambiguate_mbids(mbids, *, ab_covered=None)` picks one: **prefer an AcousticBrainz-covered recording** (the join we actually need has features), then **tie-break by the smallest MBID** so the choice is deterministic across runs. The `ab_covered` predicate is the AB dump's own presence check (`lambda m: ab_source.lookup(m) is not None`), threaded from `analyze`'s `audio_source` into the resolver so the *same* dump instance loads once; `_cmd_resolve` (no AB source) falls back to smallest-MBID, which does not change MBID coverage. The dump→TSV builder is `mb_dump.build_isrc_mbid_tsv(isrc_dump, recording_dump, out)` (offline, joins raw MB `isrc`→`recording`→`gid`; memory bounded to referenced recording ids), exposed as `music-intel build-mb-index`. Raw dump stays outside the repo.
