## V0 exit state (what "done" means)

The V0 epic (#58) exits on **pipeline correctness**, not on root presence. Decision `8186bc56` (supersedes the exit-lock decision `7b3adb41`); product-thesis follow-up tracked in #87.

- **Exit criterion = the engine runs end-to-end on the owner's real library and emits a *valid, honest-empty* `RootProfile`.** On petr's 21,118-track / 34,530-event / 553-day history the whole profile is honest-empty (0 roots / 0 tendencies). That is the system working as designed (the *Honest empty* invariant), not a failure — but the headline product (surfacing roots) was **never demonstrated on real data**. The thesis is **deferred to V1 (#87), not abandoned.**
- **Why empty — both root-producing pillars are structurally starved on V0-available sources.**
  - **Scene — coherence-starved (data, not threshold).** Last.fm alone yields 1.85% tag coverage; `derive_scene_roots` best mean NPMI at that coverage is **0.0504 at K=3** vs `coherence_floor=0.15`, and it *worsens* with K (K=5 → −0.084, K=8 → −0.262, K=13 → −0.382). Finishing the Last.fm warm adds only the obscure scattered tail → coherence falls further. Not fixable by warming and explicitly **not** by lowering the floor (hard constraint). **Text-tag pre-slice (#122, parent #109):** `MusicBrainzGenreSource` + `DiscogsStyleSource` now exist and chain onto Last.fm via `CompositeTagSource` (see §Scene root pipeline). **Combined coverage measured (#132):** a stratified ~7,000-track sample of the real 109,671-track library, run through the full chain, measured **40.57% combined coverage** — the 1.85% figure is superseded for the combined-source case (Last.fm alone is unchanged; the composite chain is what closes the gap). This is a sample estimate, not a full-library measurement (full run ≈1.5–2 days under MusicBrainz's/Discogs' rate limits); the sampled results persist in `shared_cache.jsonl` so a full run can resume from here. Whether 40.57% clears the coherence floor at the relevant K values has not yet been re-run — that is the natural next check before re-attempting scene-root derivation on real data.
  - **Audio — identity-starved AND a code gap (finding A).** 0% of tracks carry an MBID and `AcousticBrainzDump.lookup` is MBID-keyed → 0% audio ceiling regardless of dump quality. The zero is **over-determined**: even a populated dump would not help today because `analyze()` never wires the identity resolver into its seeding path (`_group_and_seed`, `analyzer.py:86-98`), `enrich_audio_features` keys on `record.mbid` (`audio.py:203`, always `None` for IFTTT tracks), and `analyze` never reads back the `resolve` subcommand's `IdentityCache`/store output. So "supply a dump" is necessary but **not sufficient** — the resolver wiring (#87 item 1) is the true prerequisite for any audio root. **→ Closed (#87, decision `4e2e49c7`):** the resolver→analyze bridge (AC-C) + live Spotify→ISRC leg (AC-A) + AB features source (AC-E) are all wired; measured MBID coverage is now **53.9%** (not 0%) and the audio pillar produces **2 real roots**. This finding is retired.
  - **Temporal — derivative.** Conditions on surviving audio/scene roots; with none upstream it is honest-empty by construction (category-ordering invariant).
- **Threshold provenance — locked for V0, validated-not-calibrated.** Every `method_params` default (`models.py`, the single source of truth) is **locked unchanged for V0** and validated *accept-side by synthetic fixtures* and *reject-side by the real run* — but **not empirically calibrated**, because V0 produced zero real candidates to calibrate against. Notably the audio HDBSCAN production values (`min_cluster_size=50`, `min_samples=10`) are **never exercised even in fixtures** (tests override to 5/2), and no accept-side threshold has ever seen real data. Empirical calibration is deferred to V1 (#87 item 4) and is **grill-gated** (calibration methodology trips the `/grill` stop-point); the hard constraint — never weaken a threshold to manufacture roots — carries forward.
- **Invariant coverage is uneven — exercised-green vs vacuous (finding D).** The honest-empty exit *exercises* the structural invariants (end-to-end run → schema-valid `RootProfile`, honest-empty, deterministic snapshot, `category_weights` inert) but leaves the *root-presence* invariants **vacuously true** (transparent-rejection of real candidates, coverage labelling, the confidence/stability/coverage promotion tests) — they pass only because no candidate ever reached them. Those are reclassified as carried, not satisfied (#87).
- **Known honest-empty limitations (carried, not bugs):**
  - **Audio transparent-rejection gap (finding G).** The audio honest-empty short-circuit (`audio.py:272`) returns an empty `quality_log`, so the 21,118 `no_mbid` drops — the dominant rejection reason on real data — leave **no trace** in the persisted artifact (only `coverage_per_category["audio"]=0.0`). Surfacing the `AudioEnrichmentReport` `no_mbid` bucket in the `RootProfile` is carried to #87.
  - **Temporal coverage is a static 1.0 (finding H).** `coverage_per_category["temporal"]` is hard-set to `1.0` in `analyzer.py` (not derived from data) — a placeholder that reads as "fully covered" while temporal is in fact honest-empty. Cosmetic at V0 (no temporal roots), flagged for #87.
