## Automated playback (#128)

**Off by default.** The agent itself plays through the #127 backfill queue via the real Spotify client, human-paced, so a user who doesn't want to manually sit through their back-catalog can still get analysis coverage. Python: `src/music_intel_mcp/automated_playback.py` (pacing/revocation/traceability logic, HTTP-free) + `SpotifyPlaybackClient` in the same module (network-touching half, mirrors `backfill_playlist.SpotifyPlaylistClient`'s callable-access-token convention). Decision `1c0f37f0` (also cited in the #109 milestone-lock summary above): automated playback is opt-in, consent-gated, and revocable — never a silent default.

- **Consent is separate from #127's opt-in, and is a local file, not an env var.** `UserStore.has_automated_playback_consent` / `grant_automated_playback_consent` / `revoke_automated_playback_consent` persist to `<data root>/automated_playback_consent.json` — deliberately distinct from `MUSIC_INTEL_BACKFILL_PLAYLIST_ENABLED` (AC1), because this drives a real playback session on the user's account, not just a queue diff. `music-intel automated-playback-consent --grant` / `--revoke` is the CLI surface; `automated-playback` refuses to start (`rc=1`) if consent isn't currently granted.
- **One mechanism serves both AC2 (human-like pacing) and AC3 (revocable mid-track).** `run_automated_playback` (`automated_playback.py`) polls `has_consent()` before each track *and* during every `poll_interval_s` (default 5s) sleep increment within a track's duration, rather than sleeping the whole duration in one shot. Revocation during playback therefore takes effect within one poll interval, not just between tracks — no separate "cancel" signal needed.
- **AC3 also pauses the real Spotify device, not just the local loop.** A mid-track revocation calls the optional `pause` callable (`_cmd_automated_playback` wires `pause=playback_client.pause`, i.e. `PUT /me/player/pause`) before returning — stopping the local Python loop alone would leave the track audibly playing on the user's device. Revocation checked *before* a track starts never calls `pause`: either nothing has played yet, or the previous track already ran its full duration on the device, so there's nothing to stop (caught by review on PR #151; fixed with a dedicated test in `test_automated_playback.py`/`test_cli_automated_playback.py`).
- **AC4's traceability is a `ListenEvent.source` discriminator, not a schema change.** `AUTOMATED_PLAYBACK_SOURCE = "agent_automated_playback"` distinguishes agent-originated plays from genuine user-initiated ones; `build_automated_play_event` stamps it. Downstream consumers (e.g. #109 S8) filter on `source == AUTOMATED_PLAYBACK_SOURCE` with no new field to read.
- **`SpotifyPlaybackClient` wraps Player Playback Control** (`user-modify-playback-state` / `user-read-playback-state` scopes, distinct from #127's `playlist-modify-*`): `PUT /me/player/play` (play), `PUT /me/player/pause` (pause), `GET /v1/tracks/{id}` for `duration_ms` — the value `run_automated_playback` paces AC2 against. Added by #159: `GET /me/player/devices` (`resolve_device_id`, name → `device_id`) and `GET /me/player` (`account_is_busy`, the AC2 gate against `is_playing` on any device).
- **`spotify_track_uri` lives in `shared_store.py`**, next to `canonical_track_id`, shared by both `backfill_playlist.SpotifyPlaylistClient` and `automated_playback.SpotifyPlaybackClient` — hoisted from two near-identical private copies after review flagged the duplication on PR #151 (INFO-severity, non-blocking, addressed anyway since it was a trivial pure-function hoist). Since #158 it accepts only a `spotify:`-prefixed key (or an already-full `spotify:track:<id>` uri) and raises `ValueError` on anything else — a bare id or an `mbid:`/`isrc:`/`name:` key is never silently normalized into a `spotify:track:<id>` uri, since that id was never resolved to a real Spotify track.
- **One combined OAuth login, not a second flow.** `spotify-login` requests `PLAYLIST_SCOPES + PLAYBACK_SCOPES` together in a single authorize URL (`spotify_user_auth.py`) — a user who has already logged in for #127 must re-run `spotify-login` once to pick up the playback scopes before `automated-playback` will authorize.
- **CLI command `music-intel automated-playback`** mirrors `backfill-playlist`'s gate order (consent → env/auth → do the work): consent check → `SPOTIFY_CLIENT_ID` check → OAuth-authorized check → fetch saved tracks → `select_backfill_tracks` (same #127 selection logic: unplayed, unanalyzed, deduped) → `SpotifyPlaybackClient.play` each track via `run_automated_playback`, appending a history event per play through `on_play`.
